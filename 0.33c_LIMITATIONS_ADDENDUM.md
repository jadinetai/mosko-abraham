## New entries

| Id | Limitation | Class | Status | Where |
|---|---|---|---|---|
| L-21 | **F-OP-01: the launcher's OK is not the official judgment for a very short run.** The official rule C5 needs a 15 s stable window (at least 13 heartbeats after OPERATIONAL). The launcher's live checks do not judge that window (design §5, L-09). So a run stopped less than about 15 s after OPERATIONAL shows `RESULT : OK (exit code 0)`, while `tools/verify_run.py` reports NOT VERIFIED (`agreement_kernel_boot` false). The kernel is not at fault. | verification | **ACCEPTED AS DOCUMENTED (D-ABR-029)**; no launcher revision | TR-0054; runs `VML-20261111T211003Z` (4 heartbeats) and `VML-20261111T215305Z` (2 heartbeats) |
| L-22 | **F-OP-02: the command-line launch path did not work for the operator.** The OP-04 Terminal commands and the `ABR-OP-06-r2.cmd` file produced no run, although the same command forms were shown to work (DEV-CMDCHECK-01, -02). Double-click launches always worked, but they cannot set a run id or an automatic stop. As a result, the operator runs carry automatic ids in `vmlauncher-0.33.2/runs` and were associated with their tests afterwards; the automatic stop was exercised only by Claude's runs. | procedure | open (a lesson for future operator campaigns) | TR-0054; `work-0.33c-op/evidence/op/ASSOCIATION*.json` |

**Operator guidance for L-21.**
- Let a run reach at least 15 s after `OPERATIONAL` (the panel's uptime 15) before pressing Q or closing the window.
- A launcher result is a live check. A run counts as evidence only once `python -I -B tools\verify_run.py <run folder>`
  reports VERIFIED.
