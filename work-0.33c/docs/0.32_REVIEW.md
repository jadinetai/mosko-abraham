## 3. The one unexpected entry, J001, and its correction

- **What happened:** J001 judged 41 falsified or control copies of W001. 40 were correct. The end-of-capture
  **control** (expected PASS) came out FAIL.
- **Why:** the control was built by cutting the log inside boot 1's last complete status round (10.1 s) and
  discarding everything after it. That also discarded heartbeats 11-15, so **C5** failed (10 heartbeats, 13 needed).
  C12 itself passed the copy and reported the cut. The same construction had passed on the development run, whose
  last round came after heartbeat 15.
- **So this was a defect in the self-test case**, not in the judge or the kernel. The recorded W001 itself shows the
  tolerance working: its boot 1 ended with a status line cut by the harness quit (`observed_at_ms=15133`), judged
  PASS and reported in `end_of_capture`. W002 ended with a partially printed round (2 lines), also PASS.
- **Correction (after `campaign close`):** `judge_selftest_032.py` now keeps every line and appends a cut round at
  the end. There are two controls: a cut line, and a partial round. J005 ran it through `supplement_032.py` with its
  expectation written first: 42/42.
- The supplement records exactly what changed since close: `tools/g032/judge_selftest_032.py`, plus the four
  post-close tools. Nothing in `kernel/` or `tools/abr_boot_001.py` changed.
- J001 stays recorded as UNEXPECTED. campaign.json is not edited.

## 4. Review notes

- **Unsafe Rust added in 0.32: none.** All 8 service modules have no `unsafe` and no `static mut` (S002). The one
  static manager uses the 0.31b `KCell`.
- **No dynamic allocation:**
  - no allocator symbol and no alloc crate (S001);
  - the service state is fixed arrays (8 entries) inside one static;
  - DIAG service names are absent from the production ELF (S002).
- **No authority:**
  - no 0.32 service grants, holds, checks or enforces authority;
  - MUTATE and INSPECT_PROTECTED queries get `CAP_MISSING` (P-09: fail closed);
  - `request()` never performs a transition.
- **No premature start:**
  - the manager refuses to start unless the kernel lifecycle is exactly OPERATIONAL;
  - it is reached only from kmain and its loop (S002);
  - no build that stops before OPERATIONAL printed a service line (N001-N008, F001, F002, F005).
- **Reason governance** (service lines; counted by script over the evidence):
  - the counted boots use only `NOT_INSTALLED` and `NONE`;
  - the DIAG builds also use `OBSERVATION_STALE`, `TARGET_UNKNOWN`, `CAP_MISSING` and `OPERATION_UNKNOWN`;
  - all of these are Appendix A or NONE (C12 and the probes parse Appendix A from the baseline);
  - no new public code (D-ABR-019 Q3 option B);
  - the 0.31b clock diagnostic lines (`ABR|CLOCK|state=DEGRADED|reason=TSC_...`) are kernel diagnostics, as in
    0.31b, and are not service status.
- **Design refinements made during implementation** (none changes an approved rule):
  1. `ServiceId` is a newtype with named constants rather than an enum, so the hosted tests can build any table. The
     production table uses only the named constants.
  2. The kernel's independent count is checked on every step, not only at readiness. A divergence is
     SVC_CONTRACT_VIOLATION.
  3. An external transition request is always refused: `SVC_INVALID_TRANSITION` if the pair is not in the matrix,
     the new `SVC_TRANSITION_MANAGER_ONLY` if it is.
  4. INSPECT_PUBLIC: `inspect` is treated as INSPECT_PROTECTED (`CAP_MISSING`); `list`/`show` are OPERATION_UNKNOWN,
     because 0.32's operation table has only `status`.
  5. S02 uses 11 malformed names instead of 9 (H003 found the gap, see PATCH_NOTES).
  6. `g6/fault_probe.py` needed no change: it does not restrict the kinds in the fault context (design §10 had
     expected a change).
- **Observed and stated, not changed:** the probe step's time is reported (`probe_us`) but not judged. So
  `svc.diagslow` showed AVAILABLE in its first status round. That was true by the definitions (no loop step had
  overrun yet), and its first loop step overran 10 ms later.

## 5. Limits and items not run

- **Not run:**
  - physical hardware, Secure Boot, ring 3, multi-CPU;
  - WHPX warm reset (still excluded, D-ABR-007); guest-requested reboot (NOT_IMPLEMENTED);
  - baseline T01-T25 (deferred to their revisions; S08 and S16 only prepare T07/T08);
  - the 0.31b D001/D002 (diag_reset label) and P001 (timing window) entries were not repeated: they test 0.29 tool
    fixes that 0.32 does not touch.
- **Cooperative limits** (by design, stated):
  - a step that never returns stops the kernel (only the harness sees it);
  - a step longer than 5 s is reported by the clock guard as a TSC jump (Y013: fail-closed, but the cause is
    misattributed).
- **A perfectly consistent liar is not detectable.** A service whose state and claims are both false in the same way
  cannot be caught by any check that reads only that service. The kernel's check catches claims its state does not
  support (Y005/Y006), not more.
- **Static checks** (S001, S002, K, P) are text and byte scans, not proofs.
- **The status is computed inside the kernel and printed.** No operator input path exists yet, so INSPECT_PUBLIC is
  exercised hosted and by a DIAGNOSTIC build.
