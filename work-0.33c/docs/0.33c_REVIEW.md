## 4. Reproducing the results

The operator path uses the existing Windows launcher only: `docs/0.33c_OPERATOR_CHECKLIST.md`. The full harness path
follows; each command writes new evidence under `work-0.33c/evidence`, so give it a new run id.

```powershell
cd Documents\Abraham\work-0.33c
$q = "C:/Users/XxUnd/abraham-toolchain/qemu/11.1.0-weil-20260811"
$efi = "third_party/limine-12.9.6/extracted/limine-binary/BOOTX64.EFI"
# production, C0-C13 (WHPX; --accel tcg for TCG)
python -I -B tools\abr_boot_001.py run --run-id <new id> --kernel ..\work-0.33\build\abraham-kernel-0.33.0-dev.elf --expect-kernel-sha256 6b95b9a27a8eedd68dd5023dbf99e73716aa1be88780ddde406099679e119a21 --qemu-dir $q --limine-efi $efi --accel whpx --profile 0.33 --restart cold
# launchpad, the 17 requests
python -I -B tools\g033\launch_probe.py run --run-id <new id> --qemu-dir $q --accel whpx --kernel ..\work-0.33\build\diag\abraham-kernel-diag-launchpad.elf --expect-kernel-sha256 89b3d6fa186753f7539aa84e6cde19532e53ac00bd752255954105fcb7755758 --limine-efi $efi --expect launchpad --seconds 12
python -I -B tools\g033c\reconcile_033c.py --out evidence\reconcile\<new id>
python -I -B tools\g3\compare_sections.py ..\work-0.33\build\abraham-kernel-0.33.0-dev.elf <any rebuild>
cd ..\vmlauncher-0.33.2
python -I -B tools\verify_run.py <run folder>                # any launcher run, any version
python -I -B tools\judge_launchpad_degraded.py selftest
```

Run ids are never reused: the harness refuses an existing one. The whole campaign (about 25 minutes) is repeated by
deriving a new driver with a new output folder and id prefix, as `tools/g033c/derive_campaign_033c.py` does.

- `tools/g033/launch_probe.py`: launchpad, degraded-clock, app-*;
- `tools/g032b/` and `tools/g031b/`: the fault probe and the service judges;
