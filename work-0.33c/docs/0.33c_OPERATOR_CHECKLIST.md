## 1. Production, and how long the heartbeat runs

1. Double-click `vmlauncher-0.33.2\Abraham-VM-Launcher.exe`, and press **Enter**.

- [ ] Every required file says `OK`. `KERNEL BOOT : OPERATIONAL at ...` (about 2.5 s), in green.
- [ ] `SERVICES`: `svc.counter RUNNING/AVAILABLE value=...`, and the value grows every 5 s.
- [ ] `APPLICATIONS`: `counterview SATISFIED | netstatus, browser UNSATISFIED (svc.netmon)`.
- [ ] `LAUNCHER CONTRACT : CONSISTENT`; nothing executed.

2. Leave it running for as long as the performance test needs: 30 minutes, an hour, or overnight. Keep the laptop
   awake for this part (Part 3 is the sleep test). Press **H** to hide the heartbeat lines if they distract; they are
   still recorded.

- [ ] The uptime keeps counting. The heartbeat has no gap. There is no red line.

3. Press **Q**.

- [ ] `KERNEL BOOT : PASS`, `SERVICES : AS DESIGNED`, `LAUNCHER CONTRACT : CONSISTENT`, `VM SHUTDOWN : CLEAN`,
  `RESULT : OK (exit code 0)`. There is no `CLOCK` row: the clock stayed OK.

## 2. The launcher contract, and a failure

4. Double-click again, and press **2** (launchpad).

- [ ] `LAUNCHER CONTRACT : CONSISTENT - 17 of 17 as designed: 9 refused, 6 not executed, 1 discovery, 1 routed;
  executed 0`. Close the window with **X**.

5. Double-click again, and press **3** (early-fail).

- [ ] `KERNEL BOOT : BOOT FAILED (as this DIAGNOSTIC build is designed to)`, and `RESULT : BOOT_FAILED (exit code 1)`.
  Press **Q**, then any key.

## 3. Sleep: a clock gap with host evidence (the 0.33c correction)

6. Double-click again, press **Enter**, and wait for OPERATIONAL and two status rounds (about 15 s).
7. Put the laptop to sleep (Start, Power, **Sleep**, or close the lid). Wait at least one minute, then wake it.

- [ ] A yellow line: `the launcher itself was not running for N s (the host suspended or stopped it)`.
- [ ] A yellow line: `the kernel reported a clock gap (heartbeat A -> B, N s skipped); host evidence: the launcher
  itself was stopped for N s at the same time, so the host suspended programs`.
- [ ] The panel's second row turns yellow: `CLOCK : DEGRADED: host suspension (launcher stopped N s) | gap reported
  by the kernel, A -> B s (N s)`. The boot row ends with `clock gap N s`.
- [ ] `SERVICES`: the counter is `UNKNOWN / OBSERVATION_STALE`, and `counterview` is UNSATISFIED. This is by design:
  stale data is never trusted.

8. Press **Q**.

- [ ] `CLOCK : DEGRADED (TSC_FORWARD_JUMP) | clock gap reported by the kernel: ... host suspension (the launcher was
  stopped N s too)`, and `RESULT : OK (exit code 0)`.
- [ ] If instead it says `cause not established` and `CLOCK_ANOMALY_CAUSE_NOT_ESTABLISHED (exit code 11)`, Windows
  did not stop the launcher during sleep. That is not an Abraham failure, but note it: it settles limitation L-11.

## 4. Refusals and clean-up

9. While one launcher is running, double-click it a second time.

- [ ] The second window says another launch is already running, starts nothing, and ends with code 4. The first keeps
  running. Quit it with **Q**.

- [ ] Task Manager (Ctrl+Shift+Esc), Details tab: no `qemu-system-x86_64.exe` is left.
- [ ] `vmlauncher-0.33.2\runs` holds one new folder `VML-<date>T<time>Z` per launch, the refused one included. Each
  has a `verdict.txt` that matches what you saw.

## 5. The same results with the tested launcher 0.33.1

10. Repeat steps 1, 3, 4 and 5 with `vmlauncher-0.33.1\Abraham-VM-Launcher.exe`. A short run is enough for step 1.

- [ ] The same verdicts and exit codes as in Parts 1 and 2.
- [ ] Optional: repeat the sleep test. 0.33.1 reports `host pause N s, reported by the kernel` and `OK (exit code 0)`
  without measuring its own stop. That wording is what 0.33c corrected (F-VML-03): it named a cause it had not
  established.
