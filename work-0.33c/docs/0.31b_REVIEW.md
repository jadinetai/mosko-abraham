## 3. Design erratum and implementation notes

- **Erratum:** `ABRAHAM_0.31b_DESIGN.md` §7 says C10 checks "exactly the 8 transitions". The lifecycle has 8
  states (plus FAILED), so a clean boot makes **7** transitions. That is what lifecycle.rs implements and what
  C10, L01 and J001 test. The approved document is left unchanged; this note corrects it.
- Kernel version 0.31.1-dev (the design did not name one).
- C10 expects 4 MEMCHECK events for memtest builds, 2 otherwise (memtest runs two extra checks).
- The 0.31a judge self-test tool takes `--profile`, so the same 37 falsifications are applied to 0.31b evidence.

## 4. Review notes (directive Step 4 / handoff §6 F)

- **Unsafe Rust added in 0.31b:** `kcell.rs` (one `unsafe impl Sync` and one `&mut` behind a re-entry flag) and
  one `cli` in `fault.rs`. `clockguard.rs`, `lifecycle.rs` and `events.rs` contain none.
- **One owner:** the production build has no private allocator. S001 shows the legacy string is absent from the
  default ELF and present in the legacy diagnostic ELF.
- **No dynamic allocation:** no allocator symbol, no alloc crate (S001). The event log is a static array (V07, S001).
- **Clock truthfulness:** uptime never decreases or wraps. After any anomaly the kernel prints
  `uptime_claimed_accurate=false` and counts the anomaly on every heartbeat.
- **NASM:** `entry.asm` is unchanged from 0.29.

## 5. Limits and items not run

- Not run: physical hardware, Secure Boot, ring 3, multi-CPU, WHPX warm reset (still excluded, D-ABR-007),
  guest-requested reboot (NOT_IMPLEMENTED), baseline T01-T25 (deferred to their revisions).
- The guard knows at most 64 live page tables; the event log holds 32 records (overwrites are counted).
- A fault while the clock, lifecycle or log is being updated reports `NONE`/`BUSY` instead of a value.
- Static checks (S001) are text and byte scans, not proofs.
