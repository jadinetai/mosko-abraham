## 2. Memory ownership model (as implemented and measured)

| Physical memory | Owner | Handed out? | Evidence |
|---|---|---|---|
| USABLE 1 MiB-4 GiB: 53,133 frames (207.6 MiB) on the tested VM | frame allocator pool | Yes | W001-T002, R001-R002: `pool_frames=53133` every boot |
| 0-1 MiB (map reports 0-0xa0000 USABLE, incl. frame 0) | ledger LOW_1MIB | No | `pool_frames_removed=160`; H02; memtest refusal of frame 0 |
| Abraham's page tables (2 today: `0x100000` PD, `0x101000` PT) | PAGE_TABLE, pinned | Never again | MEMPIN `in_pool=false free=false`; E001/E002 refusals 11/11 |
| Limine's page tables (9), GDT, stack, map, responses | BOOTLOADER_RECLAIMABLE, kept | No | MEMCHECK `pt_in_bootloader=9` |
| Kernel image (placed by Limine; moved between boots, e.g. `0xc00f000` / `0xc00c000`) | ledger KERNEL_IMAGE | No | MEMCHECK `kernel_pages=95`, contiguity verified |
| APIC registers `0xfee00000` (not RAM) | ledger MMIO | No | memtest refusal; N003 mapping intact |
| ACPI, NVS, RESERVED, RESERVED_MAPPED | firmware | No | never in pool (C9 pool-inside-USABLE check) |
| Above 4 GiB | UNMANAGED | No (0.31 limit) | none on this VM; H24 |

**Invariants (with their scope and exceptions):**
- On a clean boot (any accepted 0.31a kernel), no live page-table frame, kernel frame, APIC page or frame 0 is ever
  in the free set. This is checked twice per boot, before OPERATIONAL.
  *Exception by design:* the DIAGNOSTIC negative-control builds (`diag-legacy-collision`) violate it on purpose,
  and must be stopped by it (N001-N004).
- A frame is never free twice. A double release changes nothing and stops the kernel. *Exception:* none. The
  only double release ever executed is the deliberate one in `diag-double-release` (N005, N006).
- No frame is handed out while live. A collision quarantines the frame, latches FAULTED and stops the kernel.
  *Scope:* "live" = what the guard knows: the page tables seen by the last walk (up to 64, overflow fails the
  check), the kernel image and the APIC page.
- Exhaustion returns OUT_OF_MEMORY and writes nothing. *Scope:* the default kernel allocates only 2 frames per boot;
  exhaustion on the live kernel is shown by the DIAGNOSTIC exhaust build (E001, E002).

## 4. Review notes (handoff §6 F)

- **Unsafe Rust:** none in frame.rs. memory.rs: HHDM writes only to frames the caller owns (zeroing a new page table,
  poisoning a released frame); `UnsafeCell` access behind a re-entry flag (single CPU, no interrupt-time use).
  ptwalk.rs: volatile reads only. paging.rs unchanged in its unsafe parts.
- **NASM / register transitions:** `entry.asm` unchanged (byte-identical to 0.29).
- **Memory ownership:** one owner for USABLE RAM; the allocator starts before the first page table; there is no private
  allocator in an accepted build.
- **Failure handling:** every refusal has a registered code; serious violations latch and stop; boot-critical OOM stops.
- **Claimed enforcement:** only what the tests show, on QEMU 11.1.0 q35, 256 MiB, 1 vCPU, WHPX and TCG.
