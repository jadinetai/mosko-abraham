# ABRAHAM 0.33c: register of open limitations (D-ABR-026 Phase 5)

2026-11-10. MOSKO Laboratory 001 - Pripyat. Kernel 0.33.0-dev `6b95b9a2...` (unchanged since TR-0042). VM launcher
0.33.1 `c09f1cbf...` (tested, preserved) and 0.33.2 (the 0.33c correction).

Each limitation states what is not shown or not done, why, where it is recorded, and its class:
- **design**: chosen behaviour, documented, not a defect;
- **inherent**: a limit of what can be observed; it cannot be removed, only reported truthfully;
- **verification**: a limit of the evidence;
- **record**: a fact about the records that a reviewer must know;
- **open**: work still to do before acceptance.

None is a release blocker for the kernel. The two **open** items (L-19, L-20) are acceptance criteria A and E, which
only Echo and Jadin can close.

## Kernel and design

| Id | Limitation | Class | Where |
|---|---|---|---|
| L-01 | **A clock gap's cause cannot be established from inside the guest.** A host stop of QEMU and a guest stall produce the same `TSC_FORWARD_JUMP` + `HEARTBEAT_GAP` report. | inherent | 0.33c_AUDIT_CLARIFICATIONS.md §A |
| L-02 | **Detection window.** The clock guard reports a forward jump up to about 36 ms after it happens, so the first status round after a jump can still say `clock=OK`. That round's counter pair breaks C12's spacing rule. The official degraded-clock judge, and launcher 0.33.2, do not count C12 pair findings once DEGRADED is reported. | design | TR-0042 §5 item 3; F-VML-03 |
| L-03 | **Freezes shorter than 5 s are not reported.** The guard's threshold is 5 s between readings. A shorter freeze leaves the clock OK but breaks C12's counter progress and spacing, so the launcher reports code 10 SERVICES_NOT_AS_DESIGNED. | design | TR-0046 (P003) |
| L-04 | **Nothing executes.** The executor is ABSENT; every start request ends REFUSED or NOT_EXECUTED (option A). Real execution needs G-1..G-3 and P-09/P-17/P-46 (0.4). | design | D-ABR-022; ABRAHAM_0.33_DESIGN.md |
| L-05 | **No graphical output.** Abraham 0.33 has no framebuffer; the operator sees the serial console. | design | 0.34 First Light proposal (separate) |
| L-06 | **No network.** `dev.net0` and `svc.netmon` are DECLARED / UNAVAILABLE NOT_INSTALLED; `netstatus` and `browser` stay UNSATISFIED. P-19 holds. | design | 0.32b contract |
| L-07 | **The cybernetic data cycle is not in 0.33.** Jadin's intent is that Abraham's data self-regulates through auto-processing of its cache (defined in later revisions; central to Cyberforteca). 0.33 neither implements nor tests it, and it is not a 0.33 criterion. | design (future) | owner statement, 2026-11-09 |

## Verification

| Id | Limitation | Class | Where |
|---|---|---|---|
| L-08 | **Byte reproducibility depends on the build folder.** The ELF symbol table (`.symtab`, `.strtab`) carries the build path. Two clean builds in one folder are byte-identical; a build in another folder (work-0.33c: `3df59b73...`) differs from `6b95b9a2...` only in those sections. Every loaded section is identical. B001 was predicted UNEXPECTED for this reason before the run, and B002 proves the loaded sections equal. | verification | PREDICTIONS.json; evidence/phase4/ABR-0.33c-B002.compare.json |
| L-09 | **Live checks are not the official judgment.** The launcher's panel re-implements the rules. `tools/verify_run.py` re-judges every sealed run with the official judges. The live checks do not cover C5's 15 s stability window or C6-C8. | design | VM_LAUNCHER_DESIGN.md §5 |
| L-10 | **The degraded-clock launchpad judge is a composite, not an official judge.** It only selects and combines `launch_probe`'s own `launchpad` and `degraded-clock` rule sets, and its checks are named `composite_`. | verification | 0.33c_AUDIT_CLARIFICATIONS.md §B |
| L-11 | **Host-suspension evidence is shown on a simulated suspension, not yet on a real standby.** The 0.33.2 tests freeze the launcher and QEMU together by thread suspension (`pause_host.py`). TR-0045's real standby was run with launcher 0.33, which did not measure its own stops; the Windows power log recorded it. If a real standby does not stop the launcher (it normally does), 0.33.2 truthfully reports "cause not established". | verification | TR-0045; operator checklist, sleep step |
| L-12 | **The host-evidence rule is a heuristic.** A launcher stop of at least half the gap, ending within 30 s before the kernel's report, counts as a host suspension. A coincidental launcher stop (a debugger, an unrelated hang) at the moment of a guest stall would be misattributed to the host. | inherent | VM_LAUNCHER_DESIGN.md §5 |
| L-13 | **A stop of QEMU alone is reported "cause not established".** This covers a debugger, a test tool, or a scheduling stall that spares the launcher. The report is true: the launcher has no evidence of the stop. | inherent | launcher 0.33.2 campaign P001, P002, P004, P005 |
